# AI 智能体的「记忆」不是越多越好：IBM 8 模型实验得出的剂量曲线

给一个 AI 智能体配上「记忆」——让它从自己过去的工作中提取经验，再以指导原则的形式塞回 prompt——听起来是一个值得追求的能力。

但 IBM Research 在 Hugging Face 上发布的最新研究（2026-08-18）给出了一个不那么直觉的结论：**同一个指导原则集合，对不同能力的模型，应该用不同的剂量。**

这次实验覆盖 8 个模型，从 30B 密集模型到顶级闭源前沿系统。核心发现可以用一句话概括：记忆不是开关，是剂量。

## 「记忆」在实验中的具体含义

实验里说的「记忆」不是回放过去的对话记录，而是一组**指导原则（guideline set）**——智能体从自己的过去轨迹中蒸馏出来的策略：哪些步骤有效、哪些是错误、哪些是边缘情况的处理方式。

这套机制由 IBM 自研的 ALTK-Evolve 工具实现。它的核心循环是：

1. 智能体在 AppWorld 训练集上跑任务
2. 记录每一步的轨迹（成功、失败、中间状态）
3. 从轨迹中提取可复用的指导原则
4. 把这些原则作为额外上下文注入到未来的推理步骤

整个过程不需要更新模型权重，不需要人类标注，所有"学习"都发生在 prompt 层面。

这种"prompt 内学习"路径的优势是：每次模型升级后可以重新蒸馏一遍指导原则，而不需要重新训练模型。对于已经部署的智能体来说，这是一个相对低成本的优化方式。

## 三种模式：强模型、弱模型、饱和模型

实验覆盖 8 个模型，跨度从 30B 密集到顶级闭源。研究人员观察到了三种反复出现的模式：

**强模型 + 有提升空间**：这些模型从「完整的指导原则集合」中受益最大。DeepSeek-V3.2（671B MoE）使用完整指导原则后，任务完成率提升了 9.5 个百分点。Claude Opus 4.6 提升了 4.1 个百分点。GPT-5.5 提升了 2.9 个百分点。

这些模型有能力吸收和运用完整的指导原则集合，包括那些罕见的边缘情况经验。

**弱模型 + 精选原则**：这些模型被"过载"了。完整指导原则集合反而让它们表现下降或增加成本。Gpt-oss-120b（117B MoE）使用"精选检索"模式（一个高置信度的核心子集 + 任务相关的几个原则）时，提升了 16.1 个百分点，且 token 消耗只增加 5%。如果用完整集合，反而效果更差、成本高 50%。

**饱和模型 + 无变化**：GLM-5（745B MoE）在实验中被分类为"饱和"——加入任何形式的指导原则都没有可测量的提升。研究人员明确说明，这种命名是"描述观察到的现象，不是有证明的因果关系"。可能的原因有几种：模型已经在这些任务上接近天花板、提取的原则没有覆盖其剩余的失败模式、或者模型没有有效应用这些指导原则。

## 一个数据点：完整集合 vs 精选检索的成本差

具体到 gpt-oss-120b 的成本对比：

| 配置             | 每任务 token | 相对基线开销 |
| ---------------- | ------------ | ------------ |
| 无记忆基线       | 110K         | -            |
| 完整指导原则集合 | 166K         | +51%         |
| 精选检索         | 116K         | +5%          |

在这个例子上，**精选检索同时是效果最好和成本最低的方案**。对弱模型来说，"少而精"比"多而全"更有效。

这听起来违反直觉——按理说"经验越多越能避免错误"。但弱模型的问题不是经验少，而是它没有能力在大量上下文中识别哪些经验当前任务相关。当它试图同时处理 100 条原则时，注意力被分散，决策质量反而下降。

## 强模型的额外空间：SGC 指标的隐藏价值

实验报告了两个指标：TGC（Task Goal Completion，任务目标完成率）和 SGC（Scenario Goal Completion，场景目标完成率）。

SGC 比 TGC 更严格——它要求智能体完成场景中**每一个**变体，而不仅仅是平均情况。

在 SGC 维度上，记忆的提升幅度通常比 TGC 更大。DeepSeek-V3.2 的 SGC 提升了 16.1 个百分点（虽然 TGC 只提升 9.5）。GPT-5.5 和 Opus 4.6 在 TGC 上接近天花板（92.3 和 90.5），但 SGC 仍能提升 7.2 和 7.1 个百分点。

这说明记忆的价值在"接近满分"的模型上仍然存在——它针对的是那些剩余的失败模式，而不是平均表现。即使模型在 90% 的情况下都做对，剩下 10% 的失败模式的特征被提取为原则后，仍然可以指导未来的决策。

## 「饱和」状态的可能原因

GLM-5 在实验中完全没有从记忆中获益。研究人员没有给出一个确切的解释，但列出了几个候选原因：

第一，模型可能已经在这些任务上接近性能天花板。加入更多的原则无法突破上限。

第二，提取的原则可能没有覆盖 GLM-5 剩余的失败模式。如果 GLM-5 的失败是某些底层能力（比如空间推理或长程规划）的缺失，而不是策略问题，那么任何策略性的指导原则都无法帮助。

第三，模型可能没有有效应用这些指导原则。即使原则存在于 prompt 中，模型可能在推理时忽略了它们。

这三种可能性都指向同一个问题：记忆机制的有效性，依赖于模型本身的能力以及任务-原则的匹配度。

## 「剂量校准」作为一个产品能力

这次实验的一个隐含产品建议是：**AI 智能体平台需要提供"按模型能力分级的记忆策略"，而不是一个通用的"开启记忆"开关。**

这意味着：

对 30B 量级的开源模型，默认应该使用精选检索模式。注入完整的指导原则集合不仅无益，反而有害。

对 671B 量级的强模型（DeepSeek-V3.2 这种），应该使用完整集合。这些模型有能力处理大上下文中的所有原则。

对前沿闭源模型，完整集合仍然有价值，但 SGC 维度的提升说明记忆可以针对"接近天花板但仍有失败"的场景。

对饱和模型（如 GLM-5），记忆机制可能需要重新设计——不是注入更多经验，而是聚焦于原则质量（更针对性的提取、更清晰的表达）而非数量。

这种"剂量校准"能力目前还不是 AI 智能体平台的标配。大多数平台要么提供"有/无记忆"的二元选择，要么提供一个固定的注入量参数。这次实验表明，最优注入量是模型相关的，需要在部署时针对每个模型单独调优。

## 与传统 RAG 的对比

ALTK-Evolve 的记忆机制在概念上类似于传统 RAG（Retrieval-Augmented Generation），但有几个关键区别：

第一，**原则 vs 文档**。RAG 检索的是外部文档段落，记忆检索的是从自己过去轨迹中蒸馏出来的原则。原则是抽象的、可复用的策略，文档是具体的事实内容。

第二，**持续积累 vs 静态知识库**。RAG 的知识库通常是预构建的，记忆机制是持续积累的——每次智能体执行新任务，都可能产生新的原则。

第三，**模型能力门槛**。RAG 对模型能力的要求相对宽松（即使是弱模型也能利用检索到的文档），记忆机制对模型能力的要求更高（弱模型可能无法有效利用提取出的原则）。

第四，**与模型共同进化**。RAG 的知识库与模型是解耦的，记忆机制原则上可以随着模型的升级而重新蒸馏——同样的轨迹，用 GPT-5.5 蒸馏出的原则可能比用 GPT-3.5 蒸馏出的更精确。

这些区别决定了记忆机制不是 RAG 的替代品，而是一个补充层。在某些场景下（比如需要从执行经验中学习），记忆机制比 RAG 更合适；在其他场景下（比如需要查询特定事实），RAG 仍然是更好的选择。

## 一个值得跟踪的开放问题

这次实验的结论是基于 AppWorld 这个特定测试集。AppWorld 是一个代码生成和智能体执行环境，覆盖 60 个真实应用场景（邮件、地图、文件管理、消息发送等）。

这种环境的代表性有限——AppWorld 任务的成功率、step 数、状态复杂度与真实生产环境中的智能体执行差异较大。生产环境中的智能体往往涉及更多的外部工具调用、更长的执行链路、更复杂的失败模式。

把这些结论推广到生产环境的智能体部署，需要进一步验证。但作为对"记忆机制剂量效应"的首次系统性研究，这次实验提供了一个有价值的起点。
