# GPT-5.6-Cyber 的 95% 完成率背后，藏着一个不该被忽视的逻辑

OpenAI 发布了一个网络安全专用模型，GPT-5.6-Cyber。

官方数据里有一个数字很刺眼：它在高风险网络攻防任务上的请求完成率是 95%。作为对比，GPT-5.6 Sol 只有 1.5%，Daybreak Blue（解除部分限制的防御版本）是 2.0%。

从 1.5% 到 95%，不是优化，是重新训练出来的。

这个数字本身，以及达到这个数字的方式，是值得认真说一说的。

---

## 数据来源

本文分析基于 OpenAI 官方公告原文：

> Expanding Daybreak as the Cyber Defense Window Narrows
> https://openai.com/index/expanding-daybreak-as-the-cyber-defense-window-narrows

GPT-5.6-Cyber 的评测数据引自 OpenAI 内部评测集 Advanced Cybersecurity Completion Rate，测试任务涵盖：漏洞利用链开发（exploit-chain development）、身份验证绕过（authentication bypass）、权限提升（privilege escalation）及其他高级网络安全场景。

对比数据：GPT-5.6 Sol 基础模型 1.5%，Daybreak Blue 2.0%，GPT-5.5-Cyber 57.3%，GPT-5.6-Cyber 95.0%。

## 95% 不是一个安全优化的结果，是一个产品设计的决定

把 95% 和 1.5% 放在一起看，有一个直接的问题：这个差距是哪里来的？

官方说法是，GPT-5.6-Cyber 是用额外的数据训练出来的，专门用来"减少拒绝"（reduce refusals）。不是调低阈值，不是去掉某层过滤层，是专门针对高风险网络攻防任务做了一次额外的 RL/微调。

这意味着：达到 95% 完成率不是顺带的结果，是这次发布的本质目标。

模型厂商面临的一个经典困境是：模型默认拒绝某些危险请求，这是安全团队花了大量力气加上去的护栏。但护栏的问题是，它不区分意图。一个安全研究员在做授权漏洞验证，和一个攻击者在做真实的漏洞利用，模型看到的 prompt 可能高度相似。

OpenAI 的解法是：不做二选一，而是做分层。普通版维持拒绝率，Daybreak Red 专门给通过审查的防御研究人员提供一个"低拒绝率版本"。

这个逻辑本身是自洽的。但它带来的问题是：当一个模型专门被训练成"更少拒绝高风险网络请求"，这个能力本身会不会以其他方式扩散？

## Daybreak Red 的分层模型设计是一个值得关注的先例

把安全模型分成 Daybreak Blue 和 Daybreak Red 两层，值得单独说一下。

Daybreak Blue 是推荐的起点，给防御者的通用版，理论上覆盖漏洞发现、安全代码审查、恶意软件分析、事件响应等任务。Daybreak Red 是更高权限层，面向已授权的漏洞研究和安全测试，模型专门针对"某些高风险、双用途的网络安全任务"做了减少拒绝的训练。

这里有一个问题：两层之间的访问控制，靠的是"谁能注册 Daybreak Red"来维持的。这个控制机制的本质是信任，而不是技术上的硬隔离。

这在行业里不是没有先例。云计算里也有类似的分层权限模型，高权限账户需要有更强的身份验证和审计日志。但 API 层面上，一个模型的"安全版"和"高安全版"之间的差异，完全由访问控制决定，而不是由模型权重本身的能力差异决定——这意味着，只要有一个渠道拿到了高安全版，这个版本的能力就不再受访问控制的约束。

GPT-5.5-Cyper 的评测数据在这里提供了一个有价值的参照：57.3% 的完成率，相比 GPT-5.6 Sol 的 1.5% 已经是一个数量级的提升，但仍然远低于 GPT-5.6-Cyper 的 95%。这说明，模型的"降低拒绝"能力是可以分梯度训练出来的，不是从 1.5% 直接跳到 95%，而是有一个渐进的能力谱系。

这个谱系本身就是一个值得关注的情报。

## 95% 背后的真正问题：不是拒绝率，是拒绝的理由

从 1.5% 到 95%，不是完成率差了 60 倍，是模型对同一类请求的"理解"变了。

低拒绝率的模型，不是简单地把危险请求放过去了。它在更高层次上重新理解了这个任务：它判断这类请求在特定上下文中是合理的防御行为，因此不构成拒绝的理由。

这意味着，当 95% 的完成率被实现的时候，模型其实是具备更精准地区分"真实防御场景"和"攻击场景"的能力——至少在它被训练的范围内是这样。

但这个"更精准的区分能力"，是否在所有场景下都成立？

Advanced Cybersecurity Completion Rate 这个评测集，测的是"请求完成率"，而不是"完成后的结果质量"和"误判率"。一个模型可能在评测集上 95% 完成，但面对未见过的攻击技术时，拒绝率又会回到一个很高的水平——或者更危险地，模型会以一种新的方式误判攻击请求为合法防御。

这是从 1.5% 到 95% 的过程中，缺失的一个关键信息。

## "防御窗口在收窄"这个叙事本身，是一个值得怀疑的前提

OpenAI 这篇公告的标题核心词是：Cyber Defense Window Narrows——网络防御窗口在收窄。

这个叙事结构是：攻击者的 AI 能力在快速提升，防御者的窗口在收窄，所以 OpenAI 要把"前沿智能"交到防御者手里。

这是一个逻辑上自洽的叙事。但它隐含了一个前提：AI 辅助网络攻击的门槛，会随着大模型的普及而快速降低。

如果这个前提成立，那么 GPT-5.6-Cyper 的逻辑也是成立的：既然攻击者会用 AI，防御者更需要更好的 AI。

但如果这个前提不成立——也就是说，真正有效的 AI 网络攻击，需要的不仅仅是模型能力，还需要大量的人工定制、领域知识、和真实的网络访问权限——那么，把模型的拒绝率从 1.5% 专门提升到 95%，更像是在解决一个不存在的问题。

这个分歧，才是真正值得讨论的核心。

## 一个值得记住的数字

不管立场如何，95.0% 是一个值得记住的数字。

它是一个具体的结果，来自于一次具体的产品决策。它告诉我们的不是"AI 网络攻击有多可怕"，而是"OpenAI 选择用这种方式来解决网络防御问题"。

这次选择本身，是有代价的。代价是：当一个模型专门被训练成"更少拒绝高风险网络请求"，这个能力不再只属于授权的防御者。

这个代价，是所有类似产品决策里最值得关注的部分——不是因为它让世界变得更危险，而是因为它把一个原本分散的风险，集中在了一个中心化的 API 访问控制机制上。
