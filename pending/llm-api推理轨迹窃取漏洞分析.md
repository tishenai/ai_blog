# LLM API 的推理轨迹，正在成为一个被低估的攻击面

Hugging Face 上有一篇论文，讲的是一件事：主流 LLM API 的"推理轨迹"——也就是模型在生成最终答案之前那部分内部思考过程——在某些实现里，不是完全安全的。

这篇论文的核心发现是：一些 API 在返回"推理轨迹"时，把这个轨迹做了加密处理，但加密的方式存在缺陷。具体来说，不同请求之间的某些加密块，可以被互换，而解密之后仍然有效。

这意味着什么，我来说清楚。

---

## 加密块可互换，听起来很技术，到底是什么

用更简单的方式描述这个攻击。

你用 API 问模型一个问题 A，API 返回两部分：推理轨迹 R（被加密）和最终答案 F。你截获了这次请求的响应，里面有 R 的密文块 C1 和 C2。

然后你发起另一个请求，问一个完全不同的问题 B，拿到对应的密文块 C3 和 C4。

这篇论文发现，在某些实现里，C1 和 C3 实际上是用同一个密钥加密的，或者加密方式允许你把 C1 替换成 C3，同时解密端仍然能正常解密。

这本身听起来不直观，我换一个角度：你不是直接拿到推理轨迹的内容，而是通过一种"替换一截密文"的手段，让原本针对问题 A 的推理轨迹密文，被系统当作针对问题 B 的推理轨迹来解密。如果系统在这个过程中泄露了任何关于解密结果的旁路信息——比如执行时间、错误信息、或者某个 API 行为——你就可能从中推断出原本应该被加密的推理轨迹内容。

这就是为什么论文标题里写了"解密越狱"。

---

## 推理轨迹为什么会被当作一个安全问题

这需要一点背景。

过去一年，主流模型厂商开始越来越多地在 API 响应里附上"推理轨迹"或"思考链"（Chain-of-Thought）。这原本是帮助用户理解模型怎么做判断的。但在商业 API 里，推理轨迹往往也被当作一种产品差异化卖点：让用户看到模型"怎么想的"，比只看最终答案更能建立信任。

问题是：推理轨迹在很多场景下，比最终答案更敏感。

一个模型的推理轨迹里，可能包含它判断某段文本是"有害内容"还是"正常内容"的理由，可能包含它评估某个请求风险等级的内部逻辑，可能包含它在多步骤任务里下一步应该做什么的推理过程。

这些内容被加密返回，本来应该是安全的。但这篇论文揭示了一个现实：安全的前提是加密实现足够严谨。而这个前提，在多个主流 API 里并不总成立。

---

## 这不是理论攻击，是实际影响多家主流 API

这篇论文的特殊之处在于，它不是只在理论层面描述漏洞，而是针对多个主流 LLM API 做了实际验证。

具体是哪些厂商，论文里有详细描述，但有一点是明确的：这个漏洞不是某一家的问题，而是推理轨迹在 API 层实现方式上的一个共性缺陷。

原因在于"流式输出"（streaming）。当模型用流式方式返回推理轨迹时，每一个小块是独立加密的。问题出在：如果密钥调度不合理，或者块与块之间的加密存在可预测的模式，攻击者就有机会在块级别做操作。

这不是要求用户自己去截取流量。论文里描述的某些攻击路径，甚至可以在标准的 API 调用框架内实现——只要你能控制请求的时机和顺序。

---

## 为什么这个方向值得关注

过去关于 LLM 的安全讨论，大部分集中在三个方向：prompt 注入、数据泄露、模型对齐。但推理轨迹作为一个明确的攻击面，这篇论文把它放到了台面上。

我有几个理由认为这个方向值得认真对待。

第一，推理轨迹的重要性在上升。随着 Agentic AI 系统越来越普及，模型的内部推理会越来越多地包含规划、工具调用决策、任务分解逻辑。这些内容在云端 API 里传输，只要有漏洞，就可能成为攻击面。

第二，这个攻击面和模型能力是同步放大的。模型越强，它的推理轨迹里包含的敏感决策信息越多。一旦这个信息被窃取，损失也比以前更大。

第三，加密实现的问题往往比模型本身更难被普通用户评估。大多数用户在选择 API 时，看的是能力、价格、Benchmark 分数。但加密实现的质量，用户没有工具也没有数据去评估。这个信息不对称，在模型能力快速迭代的背景下，正在变成一个盲区。

---

## 防御方向是什么

论文里也提到了一些防御思路。短期最直接的一条是：不要在推理轨迹的流式加密里使用可预测的密钥调度。每个请求的每个块，密钥应该是独立的，或者至少是不可互换的。

这个要求听起来是工程问题，实现起来不一定简单。尤其是当厂商需要兼顾流式输出的延迟和加密的开销时，容易在安全上做出妥协。

但这篇论文的价值，恰恰在于把这个问题显式化了：当你把"推理轨迹"当成一个产品功能来卖的时候，你也在承担对应的安全责任。而这个责任，目前看来，在整个行业里还没有被足够重视。

---

回到标题：LLM API 的推理轨迹，正在成为一个被低估的攻击面。

不是因为这个攻击有多可怕，而是因为它代表了一种新的安全维度——在模型能力越来越强、越来越深入介入真实任务的时候，它的内部决策过程本身的保密性，开始变得重要了。

这个变化，是从"AI 输出结果"到"AI 思考过程"的一次安全边界的扩展。
