# OpenAI 把 Codex 改造为「ChatGPT Work」：非工程师智能体的真实控制权问题

## 为什么是 "ChatGPT Work" 不是 "Codex Pro"

产品命名不是随意的。

**Codex** 这个名字意味着"代码执行器"，受众默认是工程师。把它卖给非工程师，文案就要重写、UI 要重做、销售话术要重写。

**ChatGPT Work** 这个名字意味着"AI 帮你工作"，受众是任何一个有"工作"概念的人。

从 Codex → ChatGPT Work 的改名是 OpenAI 公开承认："**Codex 这个品牌不是问题，问题是没有非工程师愿意为它付钱**"。

支撑这个判断的是 6 月的三层数据：

| 维度               | 数字 | 解读                                    |
| ------------------ | ---- | --------------------------------------- |
| 内部员工使用 Codex | 98%  | 工程文化强，OpenAI 内部对工具采纳速度快 |
| 组织（企业）订阅   | 17%  | 企业采购是慢的，但 17% 已经在付费       |
| 个人（开发者）订阅 | <1%  | 个人开发者几乎不付费订阅                |

第三行 <1% 才是问题。**对 OpenAI 来说，Codex 在开发者市场已经基本饱和，但开发者市场本身太小（个人付费意愿低）**。要支撑 OpenAI 巨额训练投入，必须把目标市场从「1000 万开发者 × 20 美元/月」扩展到「5 亿白领 × 20 美元/月」。

这就是 ChatGPT Work 存在的原因。

## 这次改名背后的 4 个产品决策

把 Codex 包装成 ChatGPT Work，OpenAI 至少做了 4 个产品决策：

`1.` **从 IDE 形态变成对话形态**。Codex 最初是 VSCode 扩展，依赖工程概念（代码库、文件树、终端）。ChatGPT Work 退回到 ChatGPT 风格的对话界面 —— 用户输入自然语言需求，LLM 自主决定调用什么工具、怎么执行。

`2.` **从单一能力变成多步骤工作流**。Codex 早期是"代码补全"。ChatGPT Work 重新定位为"白领的多步骤工作代理" —— 写报告、订会议、整理数据、发邮件，都在一个对话里完成。

`3.` **从开发者优先变成非开发者优先**。Codex 的目标用户是知道 "Python、git、API" 是什么的人。ChatGPT Work 的目标用户是"知道 Word、Excel 是什么"的人。

`4.` **从订阅开发者工具变成订阅白领工具**。20 美元/月是 ChatGPT Plus 的同价位，不是 Codex Pro 的 200 美元/月价位。OpenAI 选择把价格定在"任何白领愿意自己掏腰包"的位置，而不是"开发者愿意让公司掏腰包"的位置。

这四个决策合起来，是把 Codex 从"AI 工程师工具"重新包装成"AI 通用劳动力"。

## 98% 内部使用 vs <1% 外部个人订阅：中间发生了什么

OpenAI 的 98% 内部使用是**工程文化**的产物 —— OpenAI 内部对 AI 工具的接受度高，工程师之间会自发扩散工具链使用。但 17% 组织订阅说明**企业采购是慢的**，需要评估、安全审查、合规流程。1% 个人订阅说明**个人开发者不愿意为自己用的 AI 工具付钱** —— 他们更习惯"免费版够用就行"或"用公司订阅的版本"。

这三个数字共同说明一个商业现实：**AI 工具的最大付费群体不是开发者、不是企业，是中产白领个人**。

但白领个人付费的前提是：工具**真的能替他们完成多步骤工作**，而不只是"写代码然后我自己执行"。

这正是 ChatGPT Work 在做的事 —— 把 AI 从"工具"重新定义为"代理人"。

## "用户愿意交出控制权吗" 是真的问题

TechCrunch 的标题 ——「用户会愿意交出控制权吗？」—— 触及了 ChatGPT Work 商业模式的根本问题。

白领工作有几个特征：

`1.` **责任不能转移**。白领的工作是「我负责的」。当 AI 替我发了邮件、替我订了会议、替我整理了报告，**最终责任还是我**。如果 AI 做错了，用户承担后果 —— 但用户又不能像程序员那样 debug 自己的工作流。

`2.` **专业判断不可替代**。白领工作里很多环节是"判断"（这封邮件该不该发？这个会议该不该开？），不是"执行"。AI 可以执行，但判断必须由人做。ChatGPT Work 让 AI 替代"执行"环节时，**判断环节的责任全部落在用户身上** —— 用户要在每一步决定"AI 这样做对不对"。

`3.` **数据边界模糊**。白领工作涉及大量敏感信息（公司财务、客户名单、内部邮件）。当 ChatGPT Work 在企业环境里执行时，这些数据流向 OpenAI 服务端是**默认会发生**的。企业的安全团队会接受这种数据外流吗？

`4.` **错误成本不对称**。白领工作里一个小错误可能产生巨大后果（错误发送的报价、错误删除的客户记录）。AI 出错的概率即使很低，乘以白领工作的执行频次，**绝对错误数会很高**。

这四个特征让"用户愿意交出控制权"这个问题变得非常具体 —— 不是"信任 AI"的问题，是"用户愿意承担 AI 出错的责任吗"的问题。

## OpenAI 的应对：分阶段交出控制权

OpenAI 在 ChatGPT Work 里采取的策略是**分阶段交出控制权**，一次性全交出会吓跑用户。

`1.` **第一阶段：建议模式**。AI 生成结果，用户必须手动确认。控制权 100% 在用户。

`2.` **第二阶段：自动执行简单任务**。AI 自动执行低风险任务（"帮我搜索 X 主题的公开信息"），高风险任务仍需确认。控制权按风险分级下放。

`3.` **第三阶段：批量执行**。用户设定规则，AI 按规则批量执行（"每天早上自动生成 X 类报告并发给 Y 列表"）。控制权大幅下放，但有规则约束。

`4.` **第四阶段：自主代理**。AI 自主决定执行什么、何时执行（"AI 监控我的收件箱，自动回复低优先级邮件"）。控制权接近完全转移。

这四个阶段对应不同用户群体 —— 工程师用户会快速跳到第四阶段（习惯 Cursor/Copilot 的自主模式），中老年白领会长期停留在第一阶段。OpenAI 不需要所有人接受第四阶段，只要**有 10% 的用户走到第三阶段**就能撑住商业模型。
